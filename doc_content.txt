1. PROJECT OVERVIEW
Business Context &amp; Scope
1.1  Business Overview
YoTech IT Solutions is a full-featured e-commerce and service platform designed for an IT business that sells hardware (laptops, PCs, mice, keyboards, components), software licenses, accessories, and provides professional tech support services. The platform serves both public visitors and registered users, with a privileged admin back-office for full business management.
1.2  Business Goals
Provide a seamless online shopping experience for IT hardware and software products
Enable customer self-service account management, order tracking, and support tickets
Empower admins with full catalog, order, user, and analytics management
Scale from MVP to a full production e-commerce platform
Build brand trust with a clean, professional blue-and-white interface
1.3  Scope of MVP
MVP Definition
The Minimum Viable Product covers the core shopping flow (browse → cart → checkout → order tracking), user authentication, admin control panel, product catalog management, and tech support ticket submission. Advanced features (AI recommendations, loyalty program, live chat) are post-MVP.

6. SECURITY
Tools, Policies &amp; Implementation
6.1  Authentication Security
Supabase Auth Security Model
All authentication is handled by Supabase Auth, which provides industry-standard security out of the box. The following measures are additionally implemented at the application layer.
Session &amp; Token Management
JWT tokens stored in HttpOnly, Secure, SameSite=Lax cookies (not localStorage)
Supabase auto-refresh tokens silently renewed before expiry
Session invalidated on logout across all tabs via Supabase BroadcastChannel
Absolute session timeout: 24 hours for customers, 8 hours for admins
Concurrent session limit: max 3 devices per user (enforced via Supabase session management)
Password Policy
Minimum 8 characters, must include uppercase, lowercase, number, and special character
Password strength indicator on registration form
bcrypt hashing with cost factor 12 (handled by Supabase)
Password reset via time-limited email link (1 hour expiry)
Prevent reuse of last 3 passwords
Rate Limiting &amp; Brute Force Protection
Supabase Auth built-in rate limiting on login, registration, and password reset endpoints
Custom rate limiting middleware (Upstash Redis or Vercel Edge Middleware): 5 failed login attempts → 15-minute lockout
CAPTCHA challenge (hCaptcha via Supabase) on registration and password reset
6.2  Authorization &amp; Access Control
Row Level Security (RLS) — Supabase
RLS enabled on ALL tables — no row access without a valid session policy
customers table: users can only read/update their own row
orders table: customers see only their own orders; admins see all
support_tickets table: customers see only their own tickets; admins see all
products table: read access for all authenticated and anonymous users; write only for admins
Admin-only tables (coupons, inventory_log, analytics): admin role required
Application-Level Route Guards
Next.js Middleware checks JWT role claim on every request to /dashboard/* (admin) and /account/* (customer)
Server Components validate session server-side before rendering protected content
API routes validate Authorization header and role before processing mutations
Admin routes return 403 if role !== &apos;admin&apos;
6.3  Input Validation &amp; Sanitization
Threat
Mitigation
SQL Injection
Supabase uses parameterized queries exclusively. No raw SQL string interpolation. RLS adds an additional layer of query isolation.
XSS (Cross-Site Scripting)
React escapes all output by default. DOMPurify used when rendering any user-provided HTML content (product descriptions, reviews). Content Security Policy headers set via next.config.js.
CSRF
SameSite=Lax cookies provide CSRF protection. API routes for mutations additionally check Origin header against NEXT_PUBLIC_SITE_URL.
Mass Assignment
Zod schemas validate and strip unknown fields on all incoming API request bodies before database writes.
File Upload Abuse
Cloudinary upload_preset restricts file type (images only: jpg, png, webp), max size (5 MB), and folder. Server-side signed uploads with Cloudinary API secret.
Path Traversal
File uploads go directly to Cloudinary via signed upload — no local filesystem writes. No file paths exposed to users.
Open Redirect
All redirect destinations validated against an allowlist of internal routes. External redirects blocked.
